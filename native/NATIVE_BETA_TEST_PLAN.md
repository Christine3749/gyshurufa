# GY 输入法：Windows 公开 Beta 回归清单

> 目标：只有全部通过，才可以把 Windows 版本称为公开 Beta；在此之前只称为内测版。
>
> 自动化测试证明 Host、IPC、离线词库和候选回传。以下清单证明真实应用兼容性；两者不能互相替代。

## 每次测试前

1. 安装待测版本，不要求关闭 Chrome、微信或其他应用。
2. 从开始菜单运行 **验证 GY 输入法安装**。必须全部通过。
3. 按 `Win + Space` 选择 **GY 输入法（拼音）**。
4. 记录 Windows 版本、显示缩放、主/副显示器、GY Host 版本和每项结果。

## 核心输入（每个目标应用都要执行）

| 操作 | 预期结果 |
|---|---|
| 输入 `nihao`，空格上屏 | 显示候选并提交中文；无拼音残留 |
| 输入 `wo`，按 `PageDown` | 进入第 2 页；数字 `1–5` 只提交当前可见候选 |
| 鼠标点击候选、左右翻页箭头 | 只向当前焦点窗口提交对应词，不向后台窗口注入数字 |
| 输入 `dz`（设置 `dz=地址\|电子邮箱`） | 地址、电子邮箱顺序置顶 |
| 选一个非首选词后，再输入同一拼音 | 被选择的词提升排序；关闭/重新打开 Host 后仍保留 |
| 单独按 `Shift` | 中/EN 状态切换；输入英文时不出现候选窗 |
| `Ctrl+C`、`Ctrl+V`、`Ctrl+X`、`Ctrl+A`、`Ctrl+F` | 全部由目标应用正常处理，不被 GY 吞掉 |
| `Shift+方向键`、大写输入 | 文本选择和大写输入正常，不误切换模式 |
| `Esc`、退格、切换窗口 | 预编辑与候选窗消失；不在新窗口误提交旧候选 |

## 显示与窗口

- 在 100%、150%、175% 缩放分别检查字体清晰度、候选窗宽度和鼠标命中。
- 使用两块不同 DPI 显示器：在两边输入、拖动窗口、切换焦点。
- 输入框位于屏幕底部/右边界时，候选窗应自动上翻或左移，不得越界、闪烁或遮住光标。

## 更新与回退

1. 保持 Chrome、微信和 Word 打开，安装一个新的 **Host-only** 版本。
2. 不重启 Windows；在现有窗口重新开始一次拼音输入。
3. 新 Host 必须自动接管，旧应用不得崩溃；快捷键和候选点击仍正确。
4. 如果新版 Host 健康检查失败，安装器必须保持旧 Host 注册值不变。
5. 只有 TSF 核心升级才允许要求“重新打开受影响应用”；不得要求强制关闭用户程序。

## 发布判定

- 任一 P0（无法输入、错误窗口上屏、吞 Ctrl 快捷键、崩溃、破坏已有输入法）失败：阻断发布。
- 每项应用矩阵至少在一台干净 Windows 用户配置文件完成一次。
- 自动化测试、安装验证器、SHA-256、许可证和 Authenticode 签名均通过后，才允许标注公开 Beta。
