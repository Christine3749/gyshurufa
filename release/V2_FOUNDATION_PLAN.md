# GY 输入法 2.0 基础工程计划

状态：**已立项，尚未发布。** 当前可安装的 `1.0.11` 只用于恢复中文输入；它不是 2.0，也不能作为 2.0 回退基线。

## 1. 2.0 的唯一承诺

任何候选窗、词库、学习、设置、登录、同步、AI 或普通更新发生故障时，用户仍能在当前文本框持续输入、选择和上屏中文。候选不足就少显示；不能用低质量词、罕见字、乱码或重复词凑数。

`release/ARCHITECTURE_CONTRACT.md` 是这条承诺的技术契约；本文件把它拆成可验收的交付顺序。

## 2. 版本边界

| 版本 | 定位 | 是否可当日常输入法 |
| --- | --- | --- |
| 1.0.11 | 临时单体恢复版本 | 仅在实际输入验收通过时可用 |
| 2.0.0-alpha | 双 Engine 与恢复机制实验 | 否；独立输入源、不可覆盖 1.0.11 |
| 2.0.0-beta | 真实宿主回归与候选窗完善 | 仅受控测试 |
| 2.0.0 | 经完整验收的稳定架构 | 是 |

2.0 alpha 必须使用**新的测试输入源身份**，不得覆盖用户正在使用的稳定输入源。只有 Bridge 迁移被单独批准后，才进行一次受控的系统输入源迁移。

## 3. 不可变核心与可更新部分

| 层 | 2.0 职责 | 普通更新是否允许替换 |
| --- | --- | --- |
| Native Bridge + Session Guard | 接键、预编辑、上屏、快照、A/B 切换 | 否 |
| Engine Slot A/B | Rime、简繁、候选模型、选词 | 是，先写入未使用槽位 |
| Candidate UI | 只渲染、鼠标、视觉动画 | 是，失败时退回原生简化候选 |
| Data / Agent | 词库快照、学习、账户、同步、AI | 是，且永不截获按键 |

任何不能满足“替换后仍可立即上屏”的功能都不准进入 Native Bridge。

## 4. 候选质量合同

候选引擎可以产生任意多的原始结果；产品池最多保留 75 个通过门槛的结果。

1. 先按当前简繁模式规范化，再去重；保留原始引擎索引以保证选中正确。
2. 每项必须通过：拼音匹配、模式匹配、有效 Unicode 文本、非重复、非半截残片。
3. 首屏 5 个必须通过高可信度词库/频率阈值；第 6–25 个使用标准阈值；第 26–75 个使用更严格阈值。
4. 任一层候选不足时，直接结束列表；不补位、不改变顺序、不以单字代替短语。
5. 每个词典和排序变更均以固定语料比较首选、前五、总数、简繁和上屏索引；结果退化即阻断发布。

质量规则必须来自共享词典、语料和用户真实选择，不能再使用“长度/字符形状”之类猜测性过滤。

## 5. 分阶段交付与门禁

| 阶段 | 交付物 | 必须通过，才能进入下一阶段 |
| --- | --- | --- |
| A：基础协议 | `SessionSnapshot v1`、版本化 IPC、Engine 测试器 | 输入中杀 Engine A，B 恢复同一拼音和候选 |
| B：数据与回退 | 只读基础词典、A/B 隔离数据、影子更新 | 新槽位失败自动回 LKG，用户无感不丢字 |
| C：平台 Bridge | macOS IMK / Windows TSF 接入 Guard | TextEdit、Terminal、WebKit/Electron 实际上屏 |
| D：候选 UI | 精确光标锚点、5×5、75 上限、键鼠分页 | 杀 UI 后 Space、Enter、数字选词仍可用 |
| E：账户能力 | Agent、同步、AI、开关 | 断网、登出、Agent 崩溃仍完整输入 |

每阶段均要求自动故障注入和人工实际文本结果；进程启动、控制器激活、日志或截图都不能代替上屏验收。

## 6. 2.0 发布阻断项

- 任何普通 UI/词库/设置更新需要覆盖系统 Bridge。
- 任一 Engine 崩溃令拼音消失、英文直出、应用卡死或无法数字选词。
- 候选出现凑数词、重复词、错简繁、错误上屏索引或超过 75 个。
- 候选锚点靠鼠标位置或文档起点猜测，导致窗口漂移、裁切或遮挡输入。
- 安装器把“包已写入磁盘”显示成“核心已激活”。

## 7. 当前第一项实现工作

已创建 `shared/session/` 中可独立编译的 `SessionSnapshot v1`、`SessionGuard` 与 Engine A/B 故障注入测试；它不链接 Rime 或平台框架。通过后才把 macOS 和 Windows 接入稳定 Bridge；候选外观改造排在该输入恢复能力之后。
