# 2026-08-04 macOS 回退基线失效

状态：已修复发布流程；1.0.11 待实际安装验收。

## 影响

将 macOS 输入法从 1.0.10 回退至标记为“已知良好”的 1.0.7 后，输入法可以启动、激活并接收 `text-event`，但绝大多数拼音直接上屏为拉丁字母。用户即使注销两次也不能恢复完整中文输入。

## 根因

1. 1.0.7 是 InputMethodKit 事件入口验证版，不是完整中文引擎。其 `CommitForCode` 仅实现 `nihao → 你好`，其余拼音原样提交。
2. 回退逻辑把 1.0.7 标为 `knownGoodVersion`，但该标记只证明历史安装/路由可用，没有证明完整中文功能。
3. 1.0.10 的候选词频/长度过滤又会删掉合法候选并错误关闭翻页，导致用户误以为只能在“坏候选”和“不能中文”之间选择。

## 排除项

- 不是 TIS 未选中：当前选中的 source 是 `wang.shurufa.inputmethod.GYInput.pinyin`。
- 不是登录会话缓存：注销后仍有新的 GYInput 进程和 `text-event`。
- 不是 Rime 缺库：1.0.10 的打包自检和 `--dump-candidates` 都通过。

## 修复

1. 1.0.11 保留 1.0.10 的 Rime 数据刷新与运行时打包。
2. 删除候选词频/长度过滤；候选顺序、翻页和原始索引由 Rime 直接提供，仍保留简繁规范化与去重。
3. 自检改为验证首选 `nihao → 你好` 且有多个候选；发布包另执行输入源、签名、Rime、升级安全测试。

## 防复发

- 只有通过真实文本验收的版本才可写入 `knownGoodVersion`。
- 安装器只能备份 `functionalBaselineVersion`；它不得根据旧状态、进程存活或物理文件存在推断“已知良好”。
- 回退验收至少覆盖 `nihao`、`zhongguo`、`changduan`、候选数字选择、简繁切换和英文直出。
- 事件路由日志、控制器激活、进程存活均只算诊断信号，不能算功能成功。
- 完成三层拆分前，macOS Bundle 更新仍需明确提示注销；拆分后才允许 Engine 热更新和 Engine 级 LKG 回退。
