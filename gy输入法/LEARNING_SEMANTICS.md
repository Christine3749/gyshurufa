# GY 学习语义跨平台契约

> v2 · 2026-08-10。适用范围：Windows（本地分层已实现）、macOS（待对齐）、未来各端。
> 基线：`GY_INPUT_METHOD_PRODUCT_STANDARD.md` §3.1。本文件定义学习等级和服务边界。

## 规则

1. **学习必须能"浮现"，不只是"重排"。** 用户真实选择过的词，无论其在引擎原始排名中的位置（哪怕在扫描窗口之外），下次输入相同编码时必须能进入候选池。
2. **学习词仍须过质量门槛。** 注入候选池前必须通过与引擎候选相同的可接受性检查（CJK 表意、长度上限）。
3. **学习词必须遵守当前简繁模式。** 注入前按当前模式做脚本归一；繁体模式下不得出现简体学习词，反之亦然。
4. **本地词频分层。** `once` 只弱保留，`memory`（累计至少 2 次）才提升，`high`（最近 7 天至少 5 次或最近 30 天至少 10 次）高优先级，`fixed` 只能由用户明确置顶产生。
5. **自定义短语与学习词同一质量体系。** 短语不绕过质量门槛和简繁归一；置顶是展示规则，不是质量豁免。
6. **输入路径不可联网。** 候选查询只读本地 Rime 快照和本地学习缓存；网络同步、词库更新和 AI 解释只能在启动、空闲或用户主动操作时执行。
7. **职责分离。** `shurufa.gyenbox.com` 负责个人体验，`ciku.gyenbox.com` 负责公共词库，`keep.gyenbox.com` 只保存用户主动确认的长期学习卡片。个人词频不能自动进入公共词库。
8. **隐私优先。** 密码框、邮箱、未提交拼音和原始按键流不得进入学习或云端；公共词频只能使用匿名聚合或人工审核数据。

## 各端实现状态

| 端 | 状态 | 位置 |
|---|---|---|
| Windows | ✅ 已实现（2026-08-10） | `native/src/PinyinEngine.cpp`：`[LearningStats]`、7/30 天窗口、弱候选、重复提升和固定词 API |
| macOS | ⏳ 待对齐 | `macos/GYInput/Sources/GYInputController.m` + `GYSettingsStore.m`：自定义短语需过简繁归一与质量门槛；未来加候选治理层（75 池）时必须内建规则 1 |
| 个人同步 | ⏳ 待实现 | 只同步用户授权的 `ime_learning` 投影，不把原始输入事件写入 Keep 剪贴板流 |
| Keep 学习卡片 | ⏳ 待实现 | `memory_cards` 独立于剪贴板，承载词源、例句、关联词和复习计划 |

## Mac 对齐时的注意点

- Mac 目前把 Rime 菜单原样透出，Rime 原生学习天然满足候选浮现规则；**风险在于将来加 GY 候选治理层时没有对齐 `once/memory/high/fixed` 分层**。
- Mac 自定义短语（`GYSettingsStore.customPhrases`）当前无脑置顶且不转简繁，违反规则 3/5，对齐时一并修。
