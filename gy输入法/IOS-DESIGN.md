## 一、定位与原则

1. 交互与手感**借鉴微信输入法 Android 版**（该版是微信输入法手感最完整的一版：
   气泡、按压、手势族、布局结构），以同机实测参数做手感校准基线（§十二）。
   借鉴边界只有三类例外：
   a. **视觉资产不借鉴**：色板、候选区骨架、字标、圆角令牌以 GY_VISUAL_IDENTITY.md
      为唯一基线；不复制微信的图标、文案、品牌元素（VI §7 红线）；
   b. **生态绑定不借鉴**：书影音/小程序/视频号智能推荐永久排除；
   c. **联网与 AI 能力不借鉴**：语音、云候选、问AI 与零联网红线冲突，远期不承诺。
2. 与 Mac/Windows 同引擎（librime）、同 rime-data、同学习格式——三端打字行为一致。
3. GY 差异点：GY Link 跨端剪贴板（§7）；候选质量治理（无表情/无怪词）；
   **可验证的零联网——iOS 上做到最硬：不请求"完全访问"，由系统沙箱强制禁止扩展联网**。
4. v0.1 只做拼音。手写、语音、表情包均不做。
5. **工程质量优先于工期与体积**：不设包体上限；词库全量内置；不为体积裁剪词库、
   架构或功能；核心逻辑测试先行（§11）。

## 二、技术基座

- Swift；**容器 App（设置/引导/GY Link 承载）+ 自定义键盘扩展（UIInputViewController）**双 target
- 部署目标 iOS 15+；键盘扩展用 UIKit 自绘（不引入重型 UI 框架）；容器 App 可用 SwiftUI
- librime 编译为 XCFramework（device arm64 + simulator arm64）；先验证仓输入法（Hamster）/
  iRime 的 iOS 集成路径，不满足则转自编译（CI 缓存构建产物），选型结论写 ADR
- rime-data 与 `macos/GYInput/Resources/rime-data/` 同源同版本，**全量内置**；
  首次启动 deploy 到 App Group 共享容器（版本戳增量，不重复拷贝）
- **`RequestsOpenAccess = NO`（不请求完全访问）**：扩展被系统沙箱禁止联网，
  零联网承诺由 iOS 系统强制执行——系统设置页截图即营销硬证据
- App Group（`group.*` 前缀进身份契约锁）承载 userdb/设置/自定义短语的容器↔扩展共享
- 代码落位：仓库 `ios/` 目录；工程生成工具 T0 决策（XcodeGen 或裸 Xcode 工程）
- 工程基线：SwiftLint 零阻断；核心逻辑（治理管线/索引映射/手势裁决/模式机）
  为不依赖 UIKit 的**纯 Swift 模块**，XCTest 单测先行；UI 层用真机矩阵验收

## 三、键盘（最大新增面，手感借鉴微信 Android 版）

1. **布局**：默认 26 键拼音全键盘；9 键为设置可选项（v0.2）。
2. **按键**：浅色圆角卡片式按键（间隙分明），按下瞬时加深，抬起回弹；
   字母键按下时上方弹出放大字符气泡（按 §十二 基线表逐帧校准）。
3. **上滑输入**：各键上滑输入角标符号/数字；长按仅出对应大写与常用符号变体。
4. **手势族完整版（v0.1 即实现）**：
   a. 删除键按住左滑连续快删、右滑恢复已删内容；
   b. 空格键/键盘面左右滑动移动光标；
   c. 删除键上滑清空、下滑撤回（恢复清空前内容）；
   d. 上滑角标、长按变体（大写+常用符号）；
   全部手势统一进**手势冲突裁决状态机**（位移阈值、时间窗、方向锁），
   阈值与速度曲线以微信输入法实测值为准（§十二），状态机先单测后联调。
   **iOS 注记**：系统键盘"长按空格进入触控板光标"是平台级肌肉记忆，
   本键盘光标手势的触发区与跟手曲线必须与之兼容，避免两套手感打架。
5. **功能区**：左下「中/EN」切换键，右下回车；逗号、句号独立键；
   空格键上显示当前模式（中/EN）。
6. **符号/数字页**：「符」键进入符号两页（常用/全量）与数字九宫格。
7. **顶部工具栏**（可收起）：GY logo、剪贴板、常用语、设置、收起键盘。
8. **深色模式跟随系统**；按键配色、按压色、气泡色全部进主题表，不写死。
9. 键盘高度三档（低/标准/高），默认标准；横屏自动紧凑布局；
   safe area 适配（刘海/灵动岛/底部 Home 条）。

## 四、候选区（复用桌面契约）

1. **收起条**：横滑候选条，首屏最多 5 个候选 + 末尾「˅」展开箭头（对齐 §5 视觉条款，
   分隔线、简/繁/EN 模式标位置与桌面一致）。
2. **展开面板**：全宽网格 5 列，纵向滚动翻页；池上限 75（3 页 × 25）与桌面相同。
3. **候选治理管线原样复用**：纯 CJK、≤12 字、滤表情/私用区/符号、去重；
   **过滤序号→Rime 原始序号映射**必须实现，且**先写映射层单元测试、再写候选 UI**
   （TDD 硬顺序；Mac 端选词错位 bug 的教训，见 MAC-HANDOFF-20260805.md 第二节）。
4. 点候选上屏；空格=首选；回车=原样拼音；退格逐字母回退，空预编辑时退格透传删除前文。

## 五、模式与切换

1. 简体 ⇄ EN：键盘「中/EN」键与候选条模式标均可切换；外接键盘 Shift 单按循环
   （对齐桌面契约：按下松开无中间键才触发；iPad/外接键盘场景契约文档 v0.2 补齐）。
2. 繁体：设置项开关；开启后候选条模式标显示「繁」。
3. 切 EN 时取消预编辑不上屏；回中文恢复上次中文模式（简/繁记忆）。
4. **敏感字段（平台差异，条款自动满足）**：iOS 对 `secureTextEntry` 与一次性验证码框
   由系统强制切回系统键盘，第三方键盘根本不会被调用——不请求完全访问即免疫
   一切敏感场景外传；验收时逐场景截图留证（对齐产品标准 §2 密码框条款）。

## 六、引擎与学习

1. librime 全量行为与桌面一致：组词、整句、组合中标点（首选+中文标点）、
   整句选词保留剩余拼音（只保留 a-z）。
2. 学习由 Rime userdb 原生承担（与 Mac 相同的"原生学习直通"）。
3. 设置内提供「清空学习」（userdb 移入回收站语义）。
4. 自定义短语：`编码=短语1|短语2` 格式与桌面互通，导入限 64KB + 导入前自动备份。

## 七、GY Link（差异化能力，v0.3 开启）

按 GY_LINK_MOBILE_COMPATIBILITY.md 的 iOS 条款执行——**主动粘贴体验**：
1. 不承诺后台静默读取系统剪贴板；用户打开 GY 键盘或容器 App 点「跨设备粘贴」时，
   从端到端加密历史拉取最新远端内容并在当前输入位置粘贴，P95 < 2 秒。
2. **技术路径默认"扩展不联网 + 容器 App 中继"**：键盘扩展保持不请求完全访问，
   网络收发全部由容器 App 承担，经 App Group 共享给扩展——保住零完全访问承诺；
   该路径 v0.3 排期前必须完成技术验证。
3. 密码/验证码/私钥/助记词默认不同步；每次同步保留来源设备、内容类型、时间与 TTL；
   内容正文不进服务端日志。
4. v0.1/v0.2 不引入 GY Link，UI 置灰并注明开启版本。

## 八、设置（容器 App，对齐四页契约精简）

1. **键盘**：布局（26/9 键）、高度三档、按键气泡开关、振动/音效开关。
2. **输入**：繁体开关、联想开关、自定义短语、清空学习；
   智能加空格（中英/中数之间）、双击空格出句号、EN 首字母自动大写
   （v0.2；默认值对齐微信输入法默认态，均可独立关闭）。
3. **外观**：主题（跟随系统/浅色/深色）、候选字号（对齐桌面 13/15/17 语义档）。
4. **账户**：GY Link 设备组（v0.3）、设备列表与撤销。

## 九、隐私红线

1. 输入功能零联网（不请求完全访问，系统级强制）；崩溃日志不含输入内容。
2. 不请求通讯录、定位、相册权限；App Store 隐私清单声明「不收集数据」。
3. 品牌红线不动：名称「输入法.网」、GY 字标、身份字段契约参照桌面版。

## 十、分期与验收

- **v0.1（M1）**：26 键键盘 + 拼音 + 候选条/展开面板 + 简/EN

  验收：与微信输入法（Android 版手感基线，iOS 版作同平台对照）同场景 AB 盲测，

## 十一、给施工端的已知坑提示（Mac 实战 + iOS 平台调研，勿重蹈）

1. 候选过滤后**必须**维护显示序号→引擎原始序号映射，否则选词错位并被学习加权；
   执行 TDD 硬顺序：映射层单测先于候选 UI（§4.3）。
2. 图标用矢量/模板可渲染资产，避免系统按文档类型兜底。
3. 菜单/弹层的回调目标必须长效——iOS 对应物：键盘 View 不得持有已销毁
   `UIInputViewController` 的引用；**扩展随时被系统回收重建**，预编辑/候选/手势态
   全部必须可重建。
4. 每端身份字段（容器 App Bundle ID / 键盘扩展 Bundle ID / App Group ID）
   先定契约锁再开工，配校验脚本。
5. **iOS 特有**：
   a. **键盘扩展内存硬顶**（系统 jetsam，超限即杀，实测安全线约 45–60MB）——
      librime + 全量词库必须 mmap 加载，T1 即实测内存预算，这是 iOS 版最大技术风险；
   b. 扩展冷启动按需创建进程：词库 deploy/加载 <300ms，重复唤出必须复用；
   c. 「完全访问」系统弹窗是全品类信任成本最高点——v0.1 不请求，引导页也不诱导开启；
   d. `secureTextEntry`/验证码框由系统自动接管为系统键盘（验收验证确实不被调用）；
   e. iPhone SE 小屏高度、横屏高度、safe area；iPad 浮动/拆分键盘（v0.4）；
   f. App Store 审核前置：privacy manifest、扩展「不收集数据」声明一致性；
   g. App Group 数据迁移：版本升级时 userdb/设置的兼容路径。

## 十二、手感校准基线：先测量、后施工

1. **测量先行**：T3/T4 施工前，对微信输入法（Android 版为主、iOS 版对照）同机实测并记录，
   形成《手感校准基线表》（存 `ios/docs/wechat-baseline.md`，随仓库演进）：
   气泡几何（尺寸/位置/弹出与消隐时序）、按压加深时延与回弹曲线、
   振动强度档位与时长、删除快删速度曲线与恢复粒度、
   光标滑动灵敏度（位移→字符步进换算）、各手势位移阈值与时间窗。
2. **行为级验收**：每项记「实测值 → GY 实现值 → 盲测结论」三列；
   盲测由非施工成员同场景 AB 执行，差异可感知即不通过。
3. **参数进表不写死**：测量值落进主题表/手势表常量层，禁止散落代码；
   微信输入法版本升级后复查基线表（每版本一次）。
4. **不借鉴清单**（防范围蔓延）：视觉资产（§一.1a）、生态推荐、语音/AI、
   联网能力、表情联想——出现即按范围蔓延打回。
