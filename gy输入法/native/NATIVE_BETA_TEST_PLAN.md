### EN 9 分放行线（Windows）

安装器和离线检查通过后，必须以**新启动的应用**完成下表。旧应用可能仍加载旧 TSF DLL，不能用作本版本证据。逐项记录应用版本、是否新启动、结果与问题编号；全部通过才可对外标注“EN 9/10”。

| 场景 | 操作 | 预期 |
|---|---|---|
| 原生文本 | 新开记事本，`nihao` 后按 Shift，再输入 `englishtest` | 未确认拼音消失；EN 只给本地英文建议，不得出现中文候选或残留拼音 |
| 浏览器正文 | 新开 Chrome/Edge 正文编辑框，切 EN，输入英文、数字、标点、快捷键 | 英文候选可忽略或接受；数字与标点原样输入，Ctrl/Alt/Win 快捷键不被截获 |
| 邮箱 / URL | 新开邮箱、地址栏或 URL 表单；简体模式直接输入，再按 Shift / Shift | 默认直通；第一次 Shift 只在当前字段临时中文，第二次返回直通；离开字段恢复全局模式 |
| 密码 / OTP | 新开密码或验证码字段；按 Shift 后输入 `nihao` | 始终原样 `nihao`；不能有预编辑、候选窗或英文辅助 |
| 英文辅助 | 开启英文辅助；正文选中 `recieve`，Ctrl+Alt+.，Enter 接受；重做后 Esc | 最多 5 个本机建议；Enter 得到 `receive`；Esc 保留 `recieve`；没有自动改写 |
| 终端 / IDE | 新开 Windows Terminal 与 VS Code，开启辅助后按 Ctrl+Alt+. | 不显示辅助候选，不吞快捷键或代码输入 |

## 每次测试前

1. 安装待测版本，不要求关闭 Chrome、微信或其他应用。
2. 从开始菜单运行 **验证 GY 输入法安装**。必须全部通过。
3. 按 `Win + Space` 选择 **GY 输入法（拼音）**。
4. 记录 Windows 版本、显示缩放、主/副显示器、GY Host 版本和每项结果。

## 核心输入（每个目标应用都要执行）

| 操作 | 预期结果 |
|---|---|
| 输入 `nihao`，空格上屏 | 显示候选并提交中文；无拼音残留 |
| 输入 `wo`，按 `PageDown` | 进入第 2 页；数字 `1–5` 只提交当前可见候选 |
| 鼠标点击候选、左右翻页箭头 | 只向当前焦点窗口提交对应词，不向后台窗口注入数字 |
| 输入 `dz`（设置 `dz=地址\|电子邮箱`） | 地址、电子邮箱顺序置顶 |
| 选一个非首选词后，再输入同一拼音 | 被选择的词提升排序；关闭/重新打开 Host 后仍保留 |
| 单独按 `Shift` | 中/EN 状态切换；EN 只出现横向英文建议，不出现中文候选 |
| 中文模式输入 `biru` 后单按 `Shift` | 取消未确认 `biru`，再进入 EN；不得上屏 `biru` 或中文候选 |
| EN 模式输入 `wo` | 默认横向 5 个英文建议；`↓` 展开为每页 8 个的单列词表；不得出现 5 × 5 或数字编号 |
| EN 模式输入英文、数字和标点 | 继续打字可忽略建议；Space／Tab／Enter 接受候选；数字与标点原样输入；切回中文后恢复中文候选 |
| 原样提交英文后在中文模式按 `, . ? ! ' "` | 自动直出英文标点；开始新的中文预编辑后恢复中文标点 |
| `Ctrl+C`、`Ctrl+V`、`Ctrl+X`、`Ctrl+A`、`Ctrl+F` | 全部由目标应用正常处理，不被 GY 吞掉 |
| 密码框、PIN 框输入字母/数字/标点 | 自动进入英文直通；不出现中文候选，不读取或改写密码内容 |
| 邮箱、登录名、URL 输入框 | 自动直通 ASCII；离开后普通中文输入状态恢复 |
| 邮箱、登录名、URL 输入框单按 `Shift` 两次 | 第一次仅在当前字段临时切回保存的中文模式；第二次回到字段 EN；切走焦点后恢复全局状态，两个动作均不得改写全局模式 |
| 密码、PIN、一次性验证码框单按 `Shift` | 仍保持 EN 直通；不得出现预编辑或候选窗 |
| 开启英文辅助后，在普通文本框选中 `recieve` 并按 `Ctrl+Alt+.` | 出现本机建议且包含 `receive`；仅选区进入临时预编辑，未选中文本不被读取或改写 |
| 英文辅助候选 | `Enter`、数字键或鼠标点击才替换选区；`Esc` 保留原词；未开启辅助时 `Ctrl+Alt+.` 必须仍交给应用 |
| 密码、PIN、URL、账号、终端、VS Code | 即使开启英文辅助，`Ctrl+Alt+.` 不得显示英文建议、读取或替换内容 |
| 中文候选窗按 `Tab` / `Shift+Tab` | 始终由目标应用切换控件，GY 不提交候选、不吞键；纯 EN 有候选时 Tab 接受当前英文词 |
| `Shift+方向键`、大写输入 | 文本选择和大写输入正常，不误切换模式 |
| `Esc`、退格、切换窗口 | 预编辑与候选窗消失；不在新窗口误提交旧候选 |

## 显示与窗口

- 在 100%、150%、175% 缩放分别检查字体清晰度、候选窗宽度和鼠标命中。
- 使用两块不同 DPI 显示器：在两边输入、拖动窗口、切换焦点。
- 输入框位于屏幕底部/右边界时，候选窗应自动上翻或左移，不得越界、闪烁或遮住光标。

## 更新与回退

1. 保持 Chrome、微信和 Word 打开，安装一个新的 **Host-only** 版本。
2. 不重启 Windows；在现有窗口重新开始一次拼音输入。
3. 新 Host 必须自动接管，旧应用不得崩溃；快捷键和候选点击仍正确。
4. 如果新版 Host 健康检查失败，安装器必须保持旧 Host 注册值不变。
5. 只有 TSF 核心升级才允许要求“重新打开受影响应用”；不得要求强制关闭用户程序。

## 发布判定

- 任一 P0（无法输入、错误窗口上屏、吞 Ctrl 快捷键、崩溃、破坏已有输入法）失败：阻断发布。
- 每项应用矩阵至少在一台干净 Windows 用户配置文件完成一次。
- 自动化测试、安装验证器、SHA-256、许可证和 Authenticode 签名均通过后，才允许标注公开 Beta。
