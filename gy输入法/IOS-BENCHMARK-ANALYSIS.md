## 二、iOS 平台差异（与 Android 版施工前提的本质不同）

1. **零联网的实现路径更硬**：不请求「完全访问」（`RequestsOpenAccess = NO`）=
   系统沙箱强制禁止扩展联网——比 Android「不申请权限」更强的可验证承诺，
   系统设置页截图即营销资产。
2. **敏感字段自动免疫**：`secureTextEntry` 与一次性验证码由系统强制切回系统键盘，
   第三方键盘根本不被调用（Android 需自己做 inputType 识别）——契约条款自动满足，验收截图留证。
3. **内存是第一红线**：键盘扩展有系统 jetsam 硬顶（超限即杀，实测安全线约 45–60MB）——
   librime + 全量词库必须 mmap 加载，T1 即实测内存预算。Android 无此约束，这是 iOS 版独有最大技术风险。
4. **扩展生命周期短**：随时被系统回收重建，预编辑/候选/手势态全部必须可重建；
   View 不得持有已销毁 `UIInputViewController` 引用。
5. **引导链路统一**：系统设置启用键盘，无厂商 ROM 碎片化走查成本；
   但「完全访问」弹窗是全品类信任成本最高点——v0.1 不请求，引导页也不诱导开启。
6. **发布前置**：App Store 审核 + privacy manifest +「不收集数据」声明一致性。
7. **GY Link 只能是主动粘贴模式**（上位契约已锁）：不承诺后台改写系统剪贴板；
   且默认走「扩展不联网 + 容器 App 中继」路径，保住零完全访问承诺（v0.3 技术验证先行）。

## 四、v0.1 验收清单（对微信输入法逐机执行）

设备矩阵：iPhone SE + 标准 + Pro Max，iOS 15–18 覆盖。

1. **手感 AB 盲测**：26 键布局、气泡位置与时序、按压加深、四类手势（快删/恢复/光标/清空撤回）——
   非施工成员同场景执行，差异可感知即不通过；
2. **输入链路**：`nihao`+空格=你好；`xiayigeban` 选词后剩余拼音保留（只 a-z）；组合中标点=首选+中文标点；
3. **候选治理**：高频拼音连打 50 组，无表情/无私用区/无重复/无 >12 字；过滤后选词逐条核对不错位；
4. **敏感场景**：密码框/验证码框逐场景验证为系统键盘接管（本键盘不被调用），截图留证；
5. **零联网**：飞行模式全流程可用；系统设置页「完全访问」未请求截图——营销资产同步产出；
6. **性能**：扩展冷启动就绪 <300ms；按键→候选 P95 <100ms；全场景遍历内存峰值 <45MB 安全线；
7. **场景**：微信聊天、Safari 地址栏、备忘录、短信验证码、WebView 表单、横屏弹幕输入。

## 五、一句话总结

微信输入法 Android 版提供了手感蓝本；iOS 的平台特性（完全访问开关、jetsam 内存硬顶、
扩展生命周期）决定了施工顺序与红线。GY 要赢的还是那三点：**候选质量治理、
可验证的零联网（iOS 上做到系统级强制）、敏感内容过滤的透明承诺**——这份契约可以直接开工。
