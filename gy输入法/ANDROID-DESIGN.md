## 一、定位与原则

1. 交互与手感**直接对齐微信输入法 Android 版**：极简、无广告、无打扰、本地优先。
   对齐的是**交互范式**（气泡、按压、手势、布局结构）；视觉资产（色板、候选区骨架、字标、
   圆角令牌）仍以 GY_VISUAL_IDENTITY.md 为唯一基线，不复制微信输入法的图标、文案或
   品牌元素（VI §7 红线）。
2. 与 Mac/Windows 同引擎（librime）、同 rime-data、同学习格式——三端打字行为一致。
3. GY 差异点：GY Link 跨端剪贴板（见 §7）；候选质量治理（无表情/无怪词）；
   可验证的零联网（连权限都不申请）。
4. v0.1 只做拼音。手写、语音、表情包均不做。
5. **工程质量优先于工期与体积**：不设包体上限；词库全量内置；不为体积裁剪词库、
   ABI 或功能；核心逻辑测试先行（见 §11）。

## 二、技术基座

- Kotlin + `InputMethodService`，minSdk 26，targetSdk 34+
- 键盘与候选区用原生 View 体系自绘（不引入重型 UI 框架）；**包体体积不作为约束**
- librime 经 JNI 接入（优先 Trime 项目维护的 Android 预编译 librime；
  验证其 boost 依赖、ABI 覆盖与 minSdk 26 匹配，不满足则转自编译，CI 缓存 NDK 构建）
- rime-data 与 `native/runtime/rime/shared/` 同源同版本，**全量内置**；构建期校验哈希
- **默认不申请联网权限**；GY Link 同步功能独立开关（§7）
- 代码落位：仓库 `android/` 目录，Gradle 标准工程
- 工程基线：ktlint + detekt 强制；核心逻辑（治理管线/索引映射/手势裁决/模式机）
  为不依赖 Android 框架的纯 JVM 模块，单测先行；UI 层用真机矩阵验收

## 三、键盘（最大新增面，微信式）

1. **布局**：默认 26 键拼音全键盘；9 键为设置可选项（v0.2）。
2. **按键**：浅色圆角卡片式按键（间隙分明），按下瞬时加深，抬起回弹；
   字母键按下时上方弹出**放大字符气泡**（微信输入法同款反馈）。
3. **上滑输入**：数字行以下各键上滑输入角标符号/数字；长按出变体（ā á ǎ à 等不做，
   长按仅出对应大写与常用符号）。
4. **删除手势族（v0.1 即实现）**：删除键按住左滑连续快删、右滑恢复已删内容；
   与上滑角标、长按变体统一做**手势冲突裁决表**（位移阈值、时间窗、方向锁），
   裁决状态机先单测后联调。
5. **功能区**：左下「中/EN」切换键，右下回车；逗号、句号独立键；
   空格键上显示当前模式（中/EN）。
6. **符号/数字页**：「符」键进入符号两页（常用/全量）与数字九宫格。
7. **顶部工具栏**（可收起）：GY logo、剪贴板、常用语、设置、收起键盘。
8. **深色模式跟随系统**；按键配色、按压色、气泡色全部进主题表，不写死。
9. 键盘高度三档（低/标准/高），默认标准；横屏自动紧凑布局。

## 四、候选区（复用桌面契约）

1. **收起条**：横滑候选条，首屏最多 5 个候选 + 末尾「˅」展开箭头（对齐 §5 视觉条款，
   分隔线、简/繁/EN 模式标位置与桌面一致）。
2. **展开面板**：全宽网格 5 列，纵向滚动翻页；池上限 75（3 页 × 25）与桌面相同。
3. **候选治理管线原样复用**：纯 CJK、≤12 字、滤表情/私用区/符号、去重；
   **过滤序号→Rime 原始序号映射**必须实现，且**先写映射层单元测试、再写候选 UI**
   （TDD 硬顺序；Mac 端选词错位 bug 的教训，见 MAC-HANDOFF-20260805.md 第二节）。
4. 点候选上屏；空格=首选；回车=原样拼音；退格逐字母回退，空预编辑时退格透传删除前文。

## 五、模式与切换

1. 简体 ⇄ EN：虚拟键盘「中/EN」键与候选条模式标均可切换；实体键盘 Shift 单按循环
   （对齐桌面契约：按下松开无中间键才触发）。
2. 繁体：设置项开关（微信输入法同位置）；开启后候选条模式标显示「繁」。
3. 切 EN 时取消预编辑不上屏；回中文恢复上次中文模式（简/繁记忆）。
4. **密码框、验证码框等敏感 inputType 变体自动识别**：强制 EN 直出、禁用学习与联想、
   不产生候选（对齐产品标准 §2 密码框条款）。

## 六、引擎与学习

1. librime 全量行为与桌面一致：组词、整句、组合中标点（首选+中文标点）、
   整句选词保留剩余拼音（只保留 a-z）。
2. 学习由 Rime userdb 原生承担（与 Mac 相同的"原生学习直通"）。
3. 设置内提供「清空学习」（userdb 移入回收站语义）。
4. 自定义短语：`编码=短语1|短语2` 格式与桌面互通，导入限 64KB + 导入前自动备份。

## 七、GY Link（差异化能力，v0.3 开启）

按 GY_LINK_MOBILE_COMPATIBILITY.md 的 Android 条款执行：
1. 用户把 GY 设为默认输入法后，按 Android 默认 IME 剪贴板权限模型读取复制内容。
2. 受保护同步默认开启；即时粘贴仅用户明确开启；密码/验证码/私钥/助记词默认不发送。
3. 在线时纯文本跨设备可用 P95 < 2 秒。
4. 每次同步保留来源设备、内容类型、时间与 TTL；内容正文不进服务端日志。
5. v0.1/v0.2 不申请联网权限，GY Link UI 置灰并说明开启版本。

## 八、设置（移动版，对齐四页契约精简）

1. **键盘**：布局（26/9 键）、高度三档、按键气泡开关、振动/音效开关。
2. **输入**：繁体开关、联想开关、自定义短语、清空学习；
   智能加空格（中英/中数之间）、双击空格出句号、EN 首字母自动大写
   （v0.2；默认对齐微信输入法默认态，均可独立关闭）。
3. **外观**：主题（跟随系统/浅色/深色）、候选字号（对齐桌面 13/15/17 语义档）。
4. **账户**：GY Link 设备组（v0.3）、设备列表与撤销。

## 九、隐私红线

1. 输入功能零联网；崩溃日志不含输入内容。
2. 不读取通讯录、位置、存储（剪贴板按 §7 边界）。
3. 品牌红线不动：名称「输入法.网」、GY 字标、身份字段契约参照桌面版。

## 十、分期与验收

- **v0.1（M1）**：26 键微信式键盘 + 拼音 + 候选条/展开面板 + 简/EN
  + 删除滑动手势 + 密码框识别 + 横屏 extract view 处理。
  验收：微信输入法并排对比，键位/气泡/按压/删除手势反馈一致；`nihao`+空格=你好；
  候选治理无表情/无重复/选词不错位（映射层单测全覆盖）；
  飞行模式全流程可用，权限声明零联网（dumpsys 截图留证）。
- **v0.2（M2）**：设置四块、繁体、主题、清空学习、自定义短语、9 键；
  光标滑动移动、上滑清空/下滑撤回手势；智能加空格/双击句号/首字母大写；
  实体键盘契约文档（方向键/数字键选词语义对齐桌面 §3.3）。
- **v0.3（M3）**：GY Link 跨端剪贴板（联网权限首次引入）；

## 十一、给施工端的已知坑提示（Mac 实战 + Android 平台调研，勿重蹈）

1. 候选过滤后**必须**维护显示序号→引擎原始序号映射，否则选词错位并被学习加权；
   执行 TDD 硬顺序：映射层单测先于候选 UI（§4.3）。
2. 图标用矢量/模板可渲染资产，避免系统按文档类型兜底。
3. 菜单/弹层的回调目标必须长效，勿挂在短生命周期实例上——Android 对应物：
   键盘 View 监听器不得持有已销毁 `InputMethodService` 的引用（配置变更/进程回收重建场景）。
4. 每端身份字段（applicationId / IME service 名 / authorities 前缀）先定契约锁再开工，配校验脚本。
5. **Android 特有**：
   a. 横屏必须显式处理 `onEvaluateFullscreenMode`（关闭或自绘 extract view），
      否则系统默认全屏输入框破坏视觉契约；
   b. 全面屏手势区：键盘底部必须适配系统手势 inset，否则最底行按键误触返回手势；
   c. 「启用 IME → 设为默认」引导链路在小米/华为/OPPO/vivo 各有拦截弹窗与安全键盘策略，
      v0.1 验收必须含逐厂商真机走查；
   d. WebView 内输入重点测 `commitText` / `setComposingText` 兼容（微信、浏览器场景）。
