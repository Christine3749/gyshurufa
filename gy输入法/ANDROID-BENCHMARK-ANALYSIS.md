# GY 输入法 Android 版 · 微信输入法对标全面分析

> 日期：2026-08-05 · 对标版本：微信输入法 3.5.2 for Android（2026-07-22，官方更新日志）
> 输入：`ANDROID-DESIGN.md`（Android 设计契约）、`GY_INPUT_METHOD_PRODUCT_STANDARD.md`、`GY_VISUAL_IDENTITY.md`、`GY_LINK_MOBILE_COMPATIBILITY.md`、Mac 端交接文档

## 一、微信输入法 Android 全景拆解（3.5.2 现状）

### 1.1 产品骨架：两种模式

| 模式 | 定位 | 能力边界 |
| --- | --- | --- |
| **隐私保护模式**（默认） | 单机本地，对标"系统自带键盘" | 全部本地输入功能可用；语音、跨设备、云候选不可用 |
| **拼写Plus 模式**（需开启完全访问+联网） | 智能增强 | 智能拼写（云候选）、拼写检查、表情/颜文字推荐、语音转文字、边写边译、跨设备同步、问AI、智能推荐（书影音/小程序） |

这与 GY「输入路径零联网 + 用户明确开启才联网」的产品标准 §6 在哲学上完全一致——**微信输入法证明了"默认本地+显式联网开关"是被市场接受的叙事**，GY 的差异化是把这个承诺做到底（默认连联网权限都不申请）。

### 1.2 功能清单分层（按对用户的可见度排序）

**A. 键盘基本功（每天每分钟都在用）**
- 26 键全键盘 / 9 键 / 手写 / 笔画 / 五笔 / 双拼，6 种输入方式
- 按键气泡、按压反馈、触感三档 + 按键音
- 上滑输入数字/符号（三档可选）；长按出大写/符号变体
- 键盘高度、宽度调节；单手模式；悬浮键盘
- 智能加空格（中英/中数之间）、首字母自动大写、双击空格出句号
- 模糊拼音

**B. 手势操作（微信输入法最被称道的一层）**
- **删除键左滑快速删除、右滑恢复已删**（删多了能滑回去）
- **上滑清空、下滑撤回删除内容**
- **键盘上左右滑动移动光标**（含长按空格触发）
- 滑行输入（手指不离键盘）

**C. 候选与学习**
- 候选词长按：**固定至首位 / 删除该词**（3.5.2 新增，此前用户呼声很高）
- 常用语、剪贴板（选词粘贴）、常用 emoji/符号记录
- 拼写检查（错别字一键纠正，拼写Plus）

**D. 跨设备（与 GY Link 正面相对的战场）**
- 跨设备复制粘贴：**6 位匹配码关联、无账号体系**、E2E 加密、词库+常用语同步、自定义设备名（3.5.2）
- 隔空传送（2026-05 起）：跨设备/面对面秒传图片与文件——已从"剪贴板"扩成"轻量文件传输"
- 换机助手

**E. 语音与 AI（拼写Plus）**
- 语音转文字：15 种方言、不限时长、**离线语音**（2025-12 大模型升级）
- 边写边译、问AI（"="触发，混元/DeepSeek）
- 文字扫描 OCR、智能推荐（微信生态书影音/小程序/视频号——**这是 GY 永远不该抄的生态绑定**）

**F. 个性化**
- 皮肤（含韩语键盘等特殊布局）、工具栏长按自定义增删调序
- 表情/颜文字联想、闪光语录、开挂模式（三连发等）

### 1.3 值得注意的动态
- 微信输入法 2026-07-20 上线 **HarmonyOS 1.0**——三端之外第四端已开。
- 演进重心明显从"输入"转向"**跨设备协同 + 语音大模型**"，基础键盘体验近两年只是小修（3.5.2 的候选长按管理是少数例外）。**基础键盘体验正是 GY 可以打平的战场；跨设备是 GY Link 可以对标的战场；语音/AI 是 GY 明确不打的战场。**

## 二、设计契约逐项对标矩阵

### 2.1 已对齐（契约覆盖且方向正确）✅

| 微信输入法能力 | GY 契约对应 | 评注 |
| --- | --- | --- |
| 26 键默认 + 9 键可选 | §3.1，9 键 v0.2 | 一致 |
| 按键气泡/按压加深 | §3.2 | 明确"微信同款"，正确 |
| 上滑输入角标 + 长按变体 | §3.3 | 微信是三档可选，GY 契约写死——可接受 |
| 中/EN 切换键 + 空格显示模式 | §3.4 | 一致 |
| 符号两页 + 数字九宫格 | §3.5 | 一致 |
| 顶部工具栏（可收起） | §3.6 | 微信工具栏可自定义调序，GY v0.1 固定——可接受 |
| 深色跟随系统 + 主题表 | §3.7 | 一致，且 GY 色板已锁定 |
| 键盘高度三档 + 横屏紧凑 | §3.8 | 微信是自由拖调，三档是合理收敛 |
| 候选条横滑 + 展开面板 | §4 | GY 用桌面契约的 5 候选+5×5 网格，信息层级清晰，**比微信的纯横滑翻页更强** |
| 候选治理（无表情/去重/≤12 字） | §4.3 | **GY 独有优势**，微信高频候选偶现表情/颜文字恰是其用户抱怨点 |
| 简/繁/EN 三模式 | §5 | 与产品标准 §2 一致 |
| 学习 + 清空学习 | §6 | 微信无"清空学习"入口，**GY 更透明** |
| 自定义短语导入 | §6.4 | 微信"常用语"等价物，GY 格式与桌面互通是加分 |
| 零联网默认 | §9 | 微信默认也要联网权限（应用市场安装即带），**GY"不申请联网权限"是更硬的可验证承诺** |
| GY Link 受保护同步/敏感过滤 | §7 | 见 §三 |

### 2.2 差距项（微信有、GY 契约未覆盖，且属于"基本功"）⚠️

按用户感知强度排序，**建议补入契约**：

| # | 能力 | 微信位置 | 建议进 GY 版本 | 理由 |
| --- | --- | --- | --- | --- |
| 1 | **删除键左滑快删、右滑恢复** | B 层核心手势 | **v0.1 补入** | 微信输入法用户口碑最高频提及的手势；自绘 View 实现成本低（删除键 touch 轨迹跟踪） |
| 2 | **键盘/空格滑动移动光标** | B 层 | v0.2 | 长拼音串改错的刚需；微信早期没有时被骂、补上后成标配 |
| 3 | **上滑清空、下滑撤回** | B 层 | v0.2 | 与 #1 同一手势族，一起设计避免手势冲突 |
| 4 | **智能加空格**（中英/中数间） | A 层 | v0.2 设置项 | 微信默认开启，年轻用户习惯已养成；EN 模式混输体验分水岭 |
| 5 | **双击空格出句号 / 首字母自动大写** | A 层 | v0.2 设置项 | 低成本高感知 |
| 6 | **模糊拼音** | A 层 | v0.3+ | librime 支持（speller/algebra），但要过候选治理管线，避免模糊音放大低质候选 |
| 7 | **候选词长按删除/固定** | C 层（3.5.2 新增） | v0.3 评估 | 需映射到 Rime userdb 负向操作（`RimeDeleteCandidate`），先做技术验证再承诺 |
| 8 | **单手模式 / 悬浮键盘** | A 层 | v0.4 | 大屏机型刚需，但非首发必需 |
| 9 | **工具栏自定义调序** | F 层 | v0.4 | 契约 §3.6 固定工具栏可先用 |
| 10 | **外接实体键盘完整契约** | 1.2.0 已支持 | **v0.1 需补文档** | 契约 §5.1 只提了 Shift；Android 平板/折叠屏外接键盘场景增长快，方向键/数字键选词语义应对齐桌面 §3.3 契约 |

### 2.3 主动不做的（契约已排除，评估结论：排除正确）✔️

- 手写/笔画/五笔/双拼：v0.1–v0.3 不做合理；但 **9 键提前到 v0.2 是对的**（中国 Android 存量用户 9 键占比高）。
- 表情/颜文字联想、闪光语录、开挂模式：与 VI §7「禁止为 AI 感/花哨干扰打字」一致，且候选治理管线本身就过滤表情——**这是差异化卖点不是缺失**。
- 智能推荐（书影音/小程序）：微信生态绑定，不可抄也不必抄。
- 语音/问AI/边写边译：与「AI 只在用户明确需要时出现」标准一致；但**官网对比页要预置话术**——"为什么没有语音输入"会是应用商店评论区第一个问题。

### 2.4 红线提醒 ⚠️

VI §7 写明「禁止模仿任何竞品的图标、候选窗比例、按钮形状或文案」。契约 §1 说"交互与视觉直接对齐微信输入法"——两者存在表述张力。建议契约补一句边界：

> 对齐的是**交互范式与手感**（气泡、按压、手势、布局结构）；视觉资产（色板、候选区骨架、字标、圆角令牌）**仍以 GY_VISUAL_IDENTITY 为准**。键盘面用浅色卡片式按键（系统键盘通用范式），候选区保持 GY 近黑底+冷白字+GY Blue 的收起/展开骨架不动。

## 三、跨设备战场：GY Link vs 微信匹配码

| 维度 | 微信输入法 | GY Link（契约 §7） | 评估 |
| --- | --- | --- | --- |
| 账号 | **无账号**，6 位匹配码 | GSYEN 账号 + 设备组 | 微信门槛更低；GY 换来的是可撤销设备列表与跨端历史，**对标话术应讲"可管理、可撤销、有历史"而非"更方便"** |
| 内容类型 | 文本 + 图片 + 文件（隔空传送） | v0.3 仅纯文本 | 接受差距，文本 P95<2s 达标即赢一半 |

| 敏感过滤 | 未公开细则 | 密码/验证码/私钥/助记词默认不发 | **GY 更透明的硬卖点**，官网应做成对比表 |

## 四、技术风险与验证项（Android 特有，按杀伤力排序）

### 4.1 🔴 包体目标 <15MB 经实测不成立，需现在决策

实测证据：`native/runtime/rime/shared` 词库源（yaml + essay.txt）约 **20MB**；编译后 `.table.bin` 虽通常小于源，但叠加以下各项：

- librime native 库：arm64-v8a 单 ABI 约 3–5MB；若兼容 armeabi-v7a/x86_64 翻倍
- rime-data 编译产物 + opencc 繁简表：约 10–18MB
- Kotlin 壳 + 资源：约 2–3MB

**单 ABI（arm64-v8a）+ 全量词库 ≈ 16–25MB**，超出目标。三个选项：

1. **放宽到 <30MB**（推荐）：微信输入法安装包 >140MB、搜狗/百度 80–120MB，30MB 以内仍是断崖式最小，营销叙事不受损；
2. 保持 <15MB：裁词库（牺牲候选质量，违背产品标准 §3.1）——**不建议**；
3. Play AAB 按 ABI 分包 + 词库内置压缩：工程复杂度高，国内分发渠道（应用宝/厂商商店）对 AAB 支持参差——**国内渠道为主则不适用**。

→ 建议：**契约目标改为 "arm64 单 ABI APK ≤ 30MB，v0.4 再评估多 ABI"**。

> **2026-08-05 产品决策（已回写契约 v2）**：不设包体上限，代码质量与候选质量优先，词库全量内置，不为体积裁剪词库、ABI 或功能。本节保留作为决策依据存档。

### 4.2 🔴 候选过滤序号→引擎原始序号映射

Mac 端实战 bug（祢蚝/妮恏 置顶并被学习加权）。Android 端 JNI 层取候选同样是"先收集后治理"，**必须在写 UI 之前先写映射层单元测试**（契约 §11.1 已列，此处升级为"先测试后 UI"的硬顺序）。

### 4.3 🟡 librime JNI 选型

- 契约方案「复用 Trime 预编译 librime」可行（Trime/同文维护 librime-android 预编译包），但需确认其 boost 依赖与 minSdk 26 匹配、ABI 覆盖；
- 备选：参考 **fcitx5-android** 的 JNI 封装结构（工程化更现代），或自编译 librime（可控但 CI 成本高）；
- 验证项：冷启动加载耗时（目标 <300ms）、userdb 写入路径在应用私有目录、升级时词库迁移策略。

### 4.4 🟡 ROM 与系统行为碎片（Android 输入法最大隐性成本）

- **默认输入法切换引导**：小米/华为/OPPO/vivo 各自有"安全键盘"与输入法切换拦截弹窗；首次启用流程（启用 IME → 设为默认）必须逐厂商真机走查，这是 v0.1 验收必须含的矩阵；
- **全面屏手势区**：键盘底部要适配手势条 inset，否则最底行按键误触返回手势；
- **键盘高度与导航栏共存**、横屏/折叠屏展开态布局（契约 §3.8 有横屏，折叠屏建议并入 v0.4 平板适配）;
- **自启动/电池优化**：GY Link v0.3 需要后台通道，届时需做厂商白名单引导（契约 v0.1/v0.2 无联网，反而免疫）。

### 4.5 🟡 Android 平台 IME 行为细节

- targetSdk 34：前台服务类型、隐式 intent 限制对 v0.3 的 GY Link 服务有影响，v0.1 免疫；
- `InputMethodService` 的 `onEvaluateFullscreenMode`（横屏全屏编辑模式）必须显式关闭或自绘 extract view，否则横屏出现系统默认全屏输入框破坏视觉契约；
- 密码框/验证码框：`inputType` 变体识别，进入 EN 直出并禁用学习与联想（对齐产品标准 §2 密码框条款）；
- WebView 内输入与 `InputConnection` 的 `commitText` vs `setComposingText` 兼容（微信/浏览器内测重点）。

### 4.6 🟢 工程治理（契约已含，强调执行）

- 身份字段先锁：applicationId、IME service name、`authorities` 前缀，配校验脚本（§11.4）；
- 图标用矢量资产（§11.2，Mac 图标战争的教训：Android 端用 `android:icon` 自适应图标 + IME 设置内 `subtype` 图标分开验证）；
- 回调目标长效（§11.3）：Android 对应物是**键盘 View 内的监听器不得持有已销毁的 InputMethodService 引用**（配置变更/进程回收后重建的场景）。

## 六、v0.1 并排验收清单（对微信输入法逐机执行）

设备矩阵建议：Pixel（原生）+ 小米 + 华为 + OPPO/vivo 各一，Android 10/12/14 覆盖。

1. **键位/手感**：26 键布局、气泡位置与大小、按压加深时延、振动反馈档位——与微信输入法同机 AB 盲测；
2. **输入链路**：`nihao`+空格=你好；`xiayigeban` 选词后剩余拼音保留（只 a-z）；组合中标点=首选+中文标点；
3. **候选治理**：高频拼音连打 50 组，候选池无表情/无私用区/无重复/无 >12 字；过滤后选词**逐条核对不错位**（映射层回归）；
4. **手势**（补入后）：删除键左滑快删/右滑恢复；上滑角标输入；长按出大写；
5. **模式**：中/EN 切换、切 EN 取消预编辑不上屏、回中恢复简/繁记忆；密码框自动 EN 直出不学习；
6. **场景**：微信聊天、浏览器地址栏、备忘录、验证码短信填写、WebView 表单；
7. **断网**：飞行模式全流程可用；抓包验证**零网络请求**（v0.1 无联网权限，此条用 `adb shell dumpsys package` 验权限声明即可成证）；
8. **性能**：键盘冷启动弹出 <300ms（微信水平），按键→候选刷新 P95 <100ms，内存常驻 <80MB；
9. **合规**：权限声明截图（无网络/无通讯录/无存储）——**这是应用商店详情页和官网对比页的营销资产，验收时同步产出**。

## 七、一句话总结

微信输入法把"基础体验扎实 + 跨设备无账号 + 隐私叙事"做成了品类标准，GY 契约选它做蓝本完全正确；**要赢的不是功能数量，而是它没做到底的三个点：候选质量治理（无表情无怪词）、可验证的零联网（连权限都不申请）、敏感内容过滤的透明承诺**——同时把 v0.1 漏掉的删除/光标手势补齐，把包体目标从 15MB 修正到 30MB，这份契约就可以直接开工。
